FLINT TABLE FILTER · HOW-TO

Export filtered Confluence table results to CSV or Excel

Hand a table to a spreadsheet, a finance system or a colleague. Decide whether you need what you are looking at or the whole original table, download it, then check the file before you rely on it.

What you will end with: from 150 orders, a current-result file with the 125 orders that are not cancelled, all of them rather than one page, in four columns in your chosen order. Alongside it, an original-table file with all 150 orders and six columns. Order IDs such as 000101 keep their leading zeros.

Before you start

The sample orders have six-digit IDs with leading zeros, customer names in several scripts, and notes that start with +, - or @, which spreadsheets can treat as formulas.

Sample orders: order-lines.csv · 150 rows, 6 columns, fictional data. If a spreadsheet app opens this file, import Order ID as text so its leading zeros survive.

  1. Edit a Confluence page and insert the Flint Table Filter macro.
  2. Inside the macro, add a native Confluence table whose first row is a header row with the column names from order-lines.csv, then enter or paste the data rows. If you paste from a spreadsheet, check that the result is an editable Confluence table rather than an image or an embedded file.
  3. Publish the page. Search, Filters, Sort, Columns, Summary, Export, Expand table and Reset view appear above the published table.

Step 1: Shape the current result

  1. Choose Filters, then Status. Set Condition to Is not one of and exclude Cancelled. The count line reads 125 of 150 rows.
  2. Set Rows per page to 25. The page controls read 1–25 of 125 · Page 1 of 5. Only 25 rows are on screen, but the export includes all 125.
  3. Choose Columns and clear Region and Note. Set Column to move to Status and choose Move earlier twice, so the visible order is Order ID, Status, Customer, Amount.
  4. Sort Amount descending.

Step 2: Download both scopes

  1. Choose Export. With Export scope set to Current result, the dialog explains: The CSV contains all matching rows in their current sort order, with visible columns in their current order.
  2. Choose Download CSV and Download XLSX. The files are named flint-table-result.csv and flint-table-result.xlsx.
  3. Change Export scope to Original table. The dialog now reads The CSV contains all 150 source rows and all 6 columns from the first table inside this macro, in original order. Search, filters, group focus and column layout do not change this export. Download both formats again: flint-table-original.csv and flint-table-original.xlsx.
  4. Choose Done.
  • flint-table-result.csvCurrent result: 125 data rows and a header, 4 columns, Amount descending
  • flint-table-result.xlsxThe same current result, one worksheet named Table, every cell stored as text
  • flint-table-original.csvOriginal table: 150 data rows and a header, 6 columns, source order
  • flint-table-original.xlsxThe same original table as XLSX

These sample files were produced from the fictional table by the export logic of Flint Table Filter 2.5.0, running outside Confluence. They show the released file format; they are not downloads from a customer site.

"000104","Ōtsuka Design","Latin America","Shipped","262.57","'+1 555 0142 callback"
  • Row counts. Open the file and count data rows below the header: 125 and 150. If your spreadsheet shows 25, you are looking at a copy of one page, not this export.
  • Leading zeros. Both formats contain 000222 exactly. A spreadsheet app can convert CSV values to numbers when it opens the file, dropping the zeros, unless you import the column as text. The XLSX stores every value as text, so 000222 stays.
  • Formula-like values. In CSV, values that begin with =, +, - or @, including headers, are prefixed with an apostrophe, so +1 555 0142 callback becomes '+1 555 0142 callback. This changes the exported data and is not a guarantee of safety in every spreadsheet. The XLSX keeps the original text as a text cell.
  • Text encoding. CSV files are UTF-8 with a byte order mark, so names such as Zoë Café and Nguyễn Thị Lan survive in apps that respect it.

We opened both sample workbooks with an independent spreadsheet library: every cell is text, and every value matches the CSV once the apostrophe prefixes are taken into account.

Group focus and grouped rows

If you chose Show rows for a group, the current result contains only that group’s rows, and the dialog says so. With Group rich rows with subtotals on, data rows follow the group order, then the sort order within each group. Group headings and subtotals never appear in CSV or XLSX.

Copy instead of downloading

The dialog also includes CSV text for copying into another tool: select all in the field, copy, and save as a UTF-8 .csv file. Copying is limited to 500,000 characters. Downloads remain available for larger results.

CSV and XLSX compared with Confluence PDF and Word

CSV and XLSX contain extracted text: no colors, status label styling or links, only the text of each cell. Confluence’s own PDF and Word exports work differently. They include the complete original table, regardless of filters, hidden columns or any reader’s view, and Confluence controls their layout. Use CSV or XLSX when you need the filtered data; use PDF or Word when you need the page as written.

If a download is unavailable

  • Wait for the current view to finish updating before copying. A search was still being applied.
  • Apply or discard your advanced rule changes before copying. An advanced rule draft is open.
  • Correct the invalid filters before copying. A filter value is invalid; see number and date formats.
  • This XLSX exceeds the 64 MB download limit. Use CSV for this table. XLSX also limits each cell to 32,767 characters. CSV downloads do not have these XLSX limits.
