FLINT MARKDOWN EXPORT · HOW-TO

Keep images and attachments working after a Markdown export

Decide which files travel with your pages, and keep the paths working after you move the export.

Finished result

Two exports of the same page: one with images only, and one that also brings a PDF and a spreadsheet. The second export leaves out an 80 MiB video with an explicit message.

Example: a site survey page

The fictional Site survey page (5001) shows two images (floor-plan.svg and Entrance photo.svg) and links a Signed survey.pdf. Two more files are attached but not shown on the page: equipment-list.csv and an 80 MiB walkthrough.mp4.

Export twice and compare

  1. Open the page, choose Apps → Export to Markdown and This page only, and choose Standard Markdown.
  2. Leave Include other attachments off and export. The footer reads Images included.
  3. Choose Export again, turn on Include other attachments, and export once more. The footer reads Images + attachments.
  4. Open the summary of the second export: Export completed with 1 warning and 1 file skipped by size limits.

Attachment filenames become lowercase and hyphenated, so Entrance photo.svg becomes entrance-photo.svg. The Markdown uses the new name. In the first export the PDF stays a Confluence link:

[Signed survey.pdf](https://example.atlassian.net/wiki/pages/viewpageattachments.action?pageId=5001&preview=Signed%20survey.pdf)

With other attachments included, the same link points to the local copy:

[Signed survey.pdf](site-survey.assets/signed-survey.pdf)

The omitted video is recorded in manifest.json, both as a page warning and in the top-level limits list:

"limits": [
  {
    "page_id": "5001",
    "file": "walkthrough.mp4",
    "size": 83886080,
    "reason": "over the 75 MB file limit"
  }
]

The message says MB; the limit is 75 MiB, or 78,643,200 bytes, for each file. Across one export, included attachments may total 300 MiB.

Keep paths working

Each page’s files sit in a .assets folder beside the page’s Markdown file, and the links are relative. Keep the extracted hierarchy together:

  • Move or copy the page file and its .assets folder together.
  • Do not flatten the folders into one directory; relative paths depend on them.
  • To list the local files a page refers to, from the export’s top folder: grep -o '](site-survey.assets/[^)]*)' site-survey.md.

The in-app preview displays common raster image formats. Check SVG images and other files in the downloaded ZIP.

Limits and recovery

  • Only attachments you can read are included. A file that fails to download keeps a Confluence link and a warning; see export warnings.
  • Large files are left out, not split. Share them separately, or export the page without them.
  • Images from external URLs stay external and are not downloaded.
  • Browser exports need enough device memory for the prepared files and the ZIP. For large attachment sets, consider a background export; it has the same size limits.
