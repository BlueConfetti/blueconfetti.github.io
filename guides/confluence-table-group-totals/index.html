FLINT TABLE FILTER · HOW-TO

Group table rows and calculate totals for a team review

Before planning, a team lead wants to know how much unfinished work each team carries. Group the table, total the estimates, rank the teams and drill into one, without copying anything into a spreadsheet.

What you will end with: 48 unfinished stories in 5 groups, ranked by total estimate with Platform first at 87 points across 16 stories. Totals cover all 48 matches, even though the table shows 25 rows per page.

Before you start

The Estimate column contains two TBD cells and one blank cell, so it is detected as Text. Summaries still read every cell that holds a number and report the rest, so you do not need to change the column type. One story has no team; it forms its own (blank cell) group.

  1. Edit a Confluence page and insert the Flint Table Filter macro.
  2. Inside the macro, add a native Confluence table whose first row is a header row with the column names from sprint-estimates.csv, then enter or paste the data rows. If you paste from a spreadsheet, check that the result is an editable Confluence table rather than an image or an embedded file.
  3. Publish the page. Search, Filters, Sort, Columns, Summary, Export, Expand table and Reset view appear above the published table.

Step 1: Narrow to unfinished work

  1. Set Rows per page to 25. Pagination does not affect any of the totals below; the small page size makes that visible.
  2. Choose Filters, then Status. Set Condition to Is not one of and exclude Done. The count line reads 48 of 64 rows over 2 pages.

Step 2: Total and group

  1. Choose Summary and set Summarize column to Estimate.
  2. Set Group rows by to Team and Group order to Highest sum first. The numeric orders appear once a summary column is chosen.

The summary box reads All 48 matching rows, before pagination: sum 209, minimum 1, maximum 13, average about 4.64, from 45 numeric · 1 blank · 2 unreadable cells. The grouped summary reports 5 groups across 48 matching rows, before data pagination:

Rows counts every story in the group; Sum adds only cells that hold numbers. Web has 8 stories but only 6 estimates, because two are TBD. Ranking uses unrounded values, groups whose sum is unavailable go last, and ties are ordered by group name.

Other orders answer other questions. Most rows first ranks by story count: Platform 16, Mobile 15, then Data and Web with 8 each. Group A to Z lists Data, Mobile, Platform, Web and finally (blank cell).

Step 4: Show subtotals in the table

Open Saved views and presentation and select Group rich rows with subtotals. Table rows follow the group order, each group under a heading such as:

Team: Mobile — 15 matching rows; Estimate subtotal: 61 (14 numeric). Totals cover the complete group across pages.
Team: Web — 8 matching rows; Estimate subtotal: 26 (6 numeric, 2 unreadable). Totals cover the complete group across pages.

When a group continues onto the next page, its heading repeats there with the same full-group totals. Headings and subtotals are display only; CSV and XLSX downloads contain data rows only.

Counting assumptions

  • Blank and unreadable cells are excluded from sums and averages, and the summary says how many.
  • Currency symbols are ignored and percentages count as percentage points. If a column mixes plain numbers, currencies or percentages, the summary warns Mixed numeric units and adds them without conversion.
  • Displayed values are rounded in your browser’s number format; ranking uses the unrounded values.
  • Merged cells repeat their value in each covered row, so a merged estimate is counted once per row. See merged cells.
  • The grouped summary shows 10 groups at a time; use Next groups for more.
