FLINT TABLE FILTER · USE CASE

Review requirements for a release without losing the master table

Release reviews need a narrow slice of a long requirements matrix. Show one release, keep only the requirements that still lack verification or evidence, and save that review without copying or editing the master table.

What you will end with: from 28 requirements, the 14 planned for release 2026-R4, and of those the 7 gaps: six not yet verified and one marked Verified with no evidence link. The view is saved for the next review, and the matrix stays complete for everyone else.

Before you start

The matrix records each requirement’s release, component, owner, status and a link to its test evidence. Statuses and links are maintained by people. Flint Table Filter does not synchronize with Jira, compute traceability or check that an evidence link works.

  1. Edit a Confluence page and insert the Flint Table Filter macro.
  2. Inside the macro, add a native Confluence table whose first row is a header row with the column names from requirements-matrix.csv, then enter or paste the data rows. If you paste from a spreadsheet, check that the result is an editable Confluence table rather than an image or an embedded file.
  3. Publish the page. Search, Filters, Sort, Columns, Summary, Export, Expand table and Reset view appear above the published table.

Step 1: Show one release

  1. Choose Filters, then Release. With few distinct values the column offers Is one of with a dropdown.
  2. In Matching values, choose 2026-R4. The value list shows 7 rows for 2026-R3, 14 for 2026-R4 and 7 for 2027-R1.
  3. Choose Done. The count line reads 14 of 28 rows.

For a quick status picture, open Summary and set Group rows by to Status: 8 Verified and 6 Implemented.

Step 2: Keep only the gaps

A requirement is a gap if it is not verified or it has no evidence link. Those two conditions use different columns, so they go in one advanced group that matches any rule.

  1. Choose Advanced groups, then Add group. Create the rule Status, Text, Does not equal, Verified, and choose Save rule.
  2. Set Match rules in group 1 to Any rule (OR).
  3. Choose Add rule to group 1. Create the rule Evidence, Text, Is empty, and choose Save rule, then Done.

The Release filter still applies, so the table shows 7 of 28 rows.

Step 3: Tidy and save the review

  1. Choose Columns and clear Release; every visible row has the same value. The column still filters while hidden.
  2. Sort by Owner so each person can find their rows.
  3. Open Saved views and presentation, enter 2026-R4 evidence gaps in View name and choose Save personal view.

Next time, choose Personal: 2026-R4 evidence gaps in Reader view and Apply view. As owners link evidence and mark rows Verified in the source table, the list shrinks. To give QA the same list, prepare it as a shared view.

Hand off the gap list

Choose Export with Current result to download the seven rows as CSV or XLSX for a release checklist. Evidence links export as their link text. See CSV and Excel exports for what the files contain.

What to know

  • Evidence cells containing an ordinary link stay clickable in the interactive table. Filters and search compare the text Confluence stores for the link.
  • The next release is one filter change away: choose 2027-R1 instead and keep the same gap rule.
  • Filtering does not restrict who can read requirements. The whole matrix stays in the page and in Confluence PDF and Word exports.
