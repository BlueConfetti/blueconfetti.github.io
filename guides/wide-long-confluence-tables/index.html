FLINT TABLE FILTER · HOW-TO

Make a wide or long Confluence table easier to read

A 12-column, 240-row case log is hard to read in a page column. Shape the view you need, in your browser, without changing the stored table.

What you will end with: a triage layout with 6 of 12 columns in a useful order, Case ID pinned while you scroll sideways, compact rows under a sticky header, 25 rows per page, and a full-screen view when you need more room, saved for reuse.

Before you start

The sample is a fictional support case log. It is large enough to need paging and horizontal scrolling, but it is a repeatable example, not a performance limit: how fast very large tables respond depends on the reader’s browser and device.

  1. Edit a Confluence page and insert the Flint Table Filter macro.
  2. Inside the macro, add a native Confluence table whose first row is a header row with the column names from support-case-log.csv, then enter or paste the data rows. If you paste from a spreadsheet, check that the result is an editable Confluence table rather than an image or an embedded file.
  3. Publish the page. Search, Filters, Sort, Columns, Summary, Export, Expand table and Reset view appear above the published table.

Step 1: Keep the columns you read

  1. Choose Columns. Under Visible columns, clear Opened, Customer, Region, Assignee, Channel and Last update. The button reads Columns (6/12). At least one column must stay visible.
  2. Use Column to move with Move earlier and Move later until the visible order is Case ID, Priority, Status, SLA due, Product, Summary. Hidden columns keep their place in the list; Restore column order undoes every move.

Hidden columns still take part in search, filters and sorting, so a search for a customer name still finds its cases.

Step 2: Set column widths

  1. Under Column widths, set Width for column to Summary and Column width to Wide (320 px).
  2. Set Case ID to Compact (120 px).
  3. For another size, choose Custom, enter a whole number from 80 to 1000 in Width in pixels and choose Apply width.

Original restores one column; Restore all original widths restores them all. Wide columns may need horizontal scrolling.

Step 3: Density, sticky header and pinning

Open Saved views and presentation:

  • Row density: Compact fits more rows on screen; Spacious suits short tables read aloud in meetings. Comfortable is the default.
  • Sticky header is on by default and keeps column names visible while you scroll down the table.
  • Pin columns while scrolling horizontally: select Case ID. Pinned columns stay at the left edge while the rest of the table scrolls sideways.

Step 4: Page size and full screen

Search, filters and sorting apply to all 240 rows before paging. Choose the page size that suits the task:

Use Previous, Next or Go to page to move between pages. Filtering shortens the list: Priority Is one of P1 with Status Is not one of Resolved and Closed leaves 20 cases on a single page.

Choose Expand table to read in a full-screen Expanded table dialog. It keeps your columns, widths, pins and filters, and offers page size buttons and page controls at the bottom. Choose Close or press Escape to return.

Step 5: Save the layout

Name the layout Triage layout in View name and choose Save personal view. It keeps columns, order, widths, density, sticky header, pins and page size in this browser. See personal views.

What authors can set for everyone

Column visibility, order, widths and page size can be author defaults. Density, sticky header and pinning are reader presentation settings; publish them as a shared view.

What to know

  • Hiding columns changes presentation only. It does not restrict access; the data stays in the page and in Confluence PDF and Word exports.
  • Current result downloads leave hidden columns out; Original table downloads include them. See CSV and Excel exports.
  • Your layout never changes the stored table or other readers’ views.
