FLINT TABLE FILTER · USE CASE

Review risks, issues and overdue actions in a Confluence register

A register only helps if the items that need attention rise to the top. Combine status, severity, due dates and ownership in one view, ranked by the score your team already maintains.

What you will end with: from 20 register entries, 16 that are not closed, and of those the 11 that are critical or high, overdue, or without an owner, ranked by Score and then by due date.

Before you start

The register below keeps a numeric Score that your team already calculates, for example likelihood multiplied by impact. Flint Table Filter reads and ranks that score; it does not calculate it, so keep the source value current.

  1. Edit a Confluence page and insert the Flint Table Filter macro.
  2. Inside the macro, add a native Confluence table whose first row is a header row with the column names from risk-register.csv, then enter or paste the data rows. If you paste from a spreadsheet, check that the result is an editable Confluence table rather than an image or an embedded file.
  3. Publish the page. Search, Filters, Sort, Columns, Summary, Export, Expand table and Reset view appear above the published table.

The worked examples use Monday 9 November 2026 as today. Relative date presets follow each reader’s device calendar, so on another day the same rule matches different rows. Where it matters, a fixed date range that reproduces the published result is included.

Step 1: Leave out closed entries

  1. Choose Filters. Set Column to Status and Condition to Is not one of.
  2. In Excluded values, choose Closed. The number beside each value counts the rows that contain it, given search and the other filters.
  3. Choose Done.

The count line reads 16 of 20 rows. Excluding Closed, rather than including Open and Monitoring, keeps any new status your team adds later in the review.

Step 2: Keep only what needs attention

An entry needs attention if any of four things is true, so these rules go in one advanced group that matches any rule. Column filters and advanced groups must both match, so closed entries stay out.

  1. Choose Advanced groups, then Add group. Create the rule Severity, Text, Equals, Critical, and choose Save rule.
  2. Set Match rules in group 1 to Any rule (OR).
  3. Use Add rule to group 1 three more times:
    • Severity, Text, Equals, High
    • Due, Date, Before, 2026-11-09
    • Owner, Text, Is empty
  4. Choose Done.

The filter button reads Filters (5): one column filter and four advanced rules. The count line reads 11 of 20 rows.

Step 3: Rank by score

Open Sort, set Sort by to Score with Order Descending, then choose Add sort column and set Then by (2) to Due, Ascending. Entries with the same score appear in due-date order.

Answer narrower questions quickly

Keep the Status exclusion and replace the advanced group with a single column condition when the meeting asks one question at a time:

Each result applies to the 16 entries that are not closed

What has no owner?Owner, Is emptyR-04, R-09, R-14

Remove a single condition with its tag above the table, or use Reset view to clear everything.

Keep overdue rolling

Before uses the date you type, so it does not move. For a starting view that stays current, use a relative date instead: set Due to Relative date, choose Last N days and enter 365. That matches due dates from the past year up to and including today, so an item due today counts as needing attention.

Compare entry types

With only the Status exclusion active, open Summary, set Summarize column to Score, Group rows by to Type and Group order to Highest average first. The 16 open entries split into Issues (5 rows, average 15.8), Risks (7 rows, average about 12.3) and Actions (4 rows, average 9.25).

What to know

  • Blank or non-numeric scores are excluded from numeric conditions and summaries. When sorting, numbers come first, then text, and blank cells stay at the bottom.
  • Filtering changes what you see, not who can see it. The complete register stays in the page and in Confluence PDF and Word exports.
  • The app does not send reminders or change statuses. Record decisions in the source table and publish the page.
  • To publish this view for every reader, copy the advanced group as described in the AND/OR guide and add Status to Default filter column with the condition Text: does not equal (ignores case) and the value Closed.
