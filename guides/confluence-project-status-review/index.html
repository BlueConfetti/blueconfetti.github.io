FLINT TABLE FILTER · USE CASE

Run a weekly project status review in Confluence

Every status meeting starts with two questions: what is stuck, and what is due this week? Answer both from the tracker your team already keeps, then publish that view so the page opens on it every week.

What you will end with: from a 24-task tracker, the 12 tasks that are blocked or due this week, sorted by due date, with estimate totals by team. Published as the page’s starting view, the “this week” rule moves forward on its own each Monday.

Before you start

You need Flint Table Filter installed with an active subscription or trial, and permission to edit the page for the last step. Readers only need to view the page.

  1. Edit a Confluence page and insert the Flint Table Filter macro.
  2. Inside the macro, add a native Confluence table whose first row is a header row with the column names from project-tracker.csv, then enter or paste the data rows. If you paste from a spreadsheet, check that the result is an editable Confluence table rather than an image or an embedded file.
  3. Publish the page. Search, Filters, Sort, Columns, Summary, Export, Expand table and Reset view appear above the published table.

The worked examples use Monday 9 November 2026 as today. Relative date presets follow each reader’s device calendar, so on another day the same rule matches different rows. Where it matters, a fixed date range that reproduces the published result is included.

Why a column filter is not enough

Filters on different columns must all match. If you choose Status Is one of Blocked and then add a Due condition of This week, the table shows only tasks that are blocked and due this week. In the sample that is one task, PRJ-117. The meeting needs blocked tasks or tasks due this week, so the two rules belong in one advanced group set to match any rule.

Step 1: Find blocked work or work due this week

  1. Choose Filters, then Advanced groups.
  2. Choose Add group. In the new rule, set Rule column to Status, Rule type to Text, Rule condition to Equals and Rule value to Blocked. Choose Save rule.
  3. Set Match rules in group 1 to Any rule (OR).
  4. Choose Add rule to group 1. Set Rule column to Due, keep Rule type as Date, set Rule condition to Relative date and Rule date preset to This week. Choose Save rule, then Done.

The filter tag reads Advanced: 1 group, 2 rules and the count line reads 12 of 24 rows. Weeks run Monday through Sunday, so on 9 November the preset covers 9 to 15 November. Four tasks are blocked and nine are due this week; PRJ-117 is both.

Equals ignores case, so blocked works too. If your Status column uses Confluence status labels, the rule compares the label’s text.

Step 2: Sort by due date

Choose Sort in the Due column header, or open Sort, set Sort by to Due and Order to Ascending. Overdue blocked work rises to the top.

Step 4: Make it the page’s starting view

Your filters, sort and summary so far are yours alone and reset when the page reloads. To open the page on this view for every reader, copy the advanced rule into the macro settings and add the matching defaults.

  1. In Advanced groups, choose Copy advanced filter settings. Select everything in Advanced filter settings and copy it. Choose Back to advanced groups.
  2. Edit the page and open the Flint Table Filter macro settings.
  3. Set Settings section to Column filters and advanced rules and paste into Default advanced filter groups.
  4. Fill in the remaining sections as shown below. Starting view preview reports 12 of 24 rows match and previews the first five rows.
  5. Choose Save settings, then publish the page.

The copied settings refer to column headers by name and store the preset, not the dates, which is why the view rolls forward each week:

{
  "version": 1,
  "match": "all",
  "groups": [
    {
      "match": "any",
      "rules": [
        {
          "header": "Status",
          "condition": {
            "type": "text",
            "dateFormat": "iso",
            "operator": "equals",
            "value": "Blocked",
            "valueTo": "",
            "preset": ""
          }
        },
        {
          "header": "Due",
          "condition": {
            "type": "date",
            "dateFormat": "iso",
            "operator": "relative",
            "value": "",
            "valueTo": "",
            "preset": "thisWeek"
          }
        }
      ]
    }
  ]
}

After publishing, readers see Author defaults currently applied: Due ascending; advanced filters; summary: Estimate; group by: Team; group order: Most rows first. Anyone can narrow further during the meeting, for example to one team, and Reset view returns them to this starting view.

Run the meeting

  • Update statuses and due dates in the source table as decisions are made, then publish. The app reads the table; it does not change task data.
  • Each attendee’s changes affect only their own view. Share a screen if everyone should follow the same narrowing.
  • To reproduce this exact result on another day, replace the relative rule with Due Between 2026-11-09 and 2026-11-15. The same 12 tasks match.

What to know

  • Relative dates use each reader’s device calendar. Readers in time zones on either side of midnight can briefly see different weeks.
  • The default sort uses one column; readers can add more with Add sort column.
  • Defaults shape the starting view only. Every reader can still reach all 24 rows, and Confluence PDF and Word exports contain the complete original table.
  • If a header used by a default is renamed, the page shows Check the table's default view with the skipped setting. Update the macro settings to the new header name.
